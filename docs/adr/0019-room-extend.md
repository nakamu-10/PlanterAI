# 0019 部屋の床と壁を、部屋の外へ延ばしておく

- 日付：2026-11-27

## 背景

- 部屋の glb
  は、床と壁が部屋の大きさで切れていた。画面の端が部屋の外にかかると、アプリの緑の地との境がくっきり出て、部屋が切り抜きに見えた（#156）
- 見回せる範囲（0018）は、部屋の床と壁の箱で測っていた。床と壁を延ばすと、範囲も一緒に広がってしまう

## 決定

- Blender で、床を右と手前へ、奥の壁を右へ、左の壁を手前へ、それぞれ 4m
  延ばす。木目・幅木・壁の上の縁も、部屋と同じ形で続ける。延ばした部品は、コレクション
  `static_outside` に入れる
- 延ばした所は、部屋の中と別の絵（1024px）に焼く。材質は `baked_outside`
  にする。アプリは、名前が `baked`
  で始まる材質を、どちらも焼いた絵としてそのまま出す
- 延ばした部品は、書き出す前に1つのメッシュ `static_outside`
  に結合する。材質も絵も
  同じで、触ったときの役目も持たないので、分けておく理由がない
- 見回せる範囲は、延ばす前の部屋の床と壁の厚みのまま変えない。Blender に目印
  `view_area` を置き、アプリはその箱で範囲を測ってから外す
- 延ばした所は、物を置かず、キャラも歩かせない。画面の端を埋めるためだけに置く

## 理由

- 1枚の絵のまま広げると、部屋の中の細かさが落ちる。外は画面の端にしか写らないので、粗い絵でよい
- 部屋そのものの範囲を目印で持てば、外をどれだけ延ばしても見回せる範囲は変わらない
- 結合しないと、外の部品だけで約90個のメッシュになり、部屋の描画の呼び出しがおよそ倍になる。古いスマホではコマ落ちの元になる
- glb は 660KB から 1.15MB になった。キャラの
  glb（0.9〜1.5MB）と同じくらいで、読み込みは待てる長さ

## 代替案

- three.js
  で、部屋の外に色の板を置く：焼いた光の明るさの変わり方と合わず、継ぎ目が出る
- 画面の端をぼかして、背景の色に溶かす：部屋が浮いて見えるのは変わらない
- 床と壁の模様を繰り返し貼り、光だけを別に焼く：材質の作りを変える量が大きい
