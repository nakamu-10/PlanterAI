# 0014 日照の予告は14時台だけにし、天気はその日の1回分を覚える

## 状況

11/10（雨）のカラテアに、19:50 に「今すぐ明るい場所に引っ越しさせて」、20:00
に「２日前から光が足りなくて不安」と続けて届いた。

- 予告は「15時〜20時の、最初に不足見込みになった回」に出す作りだった。15時台に出なければ後ろへずれ込み、日が沈んでから「今すぐ移して」と頼んでいた
- 雨の日は予告を止める（ADR
  0013）はずだったが、天気はセンサーの値が届くたび（10分ごと）に取りに行っていた。19:50
  に1回取りそこね、晴れ扱いになった。15時台は取れていて、予告を止めていたとみられる

## 決定

- 予告は14時台だけに出す。15時を過ぎたら出さず、20時の締めだけにする。遅すぎると、移しても間に合わない
- 14時の基準は目標の0.3倍にする。10/2〜11/10
  の実測（目標8,000）で、達成した日の14時の最低は0.34倍、不足した日の最高は0.71倍で、15時ほどきれいに分かれない。午後の西日で追い上げる日があるため、達成する日には予告しない側に寄せた。不足した23日のうち16日に予告が出る
- その日に最初に取れた予報を
  `daily_weather`（日付と場所で1行）に覚え、その日の判定はそれを使う
- 場所を設定してあって天気が取れなかったときは、送るのを次の回に回す。予告は14時台が過ぎれば出さない。締めは21時になったら晴れ扱いで送る

## 結果

- 15〜20時は判定ジョブが DB を叩かなくなる
- 天気の API を呼ぶのは、ほぼ1日1回になる
- 14時の予報は、その日の午後が晴れても変わらない。午後から晴れた日を雨の日として扱うことがある
