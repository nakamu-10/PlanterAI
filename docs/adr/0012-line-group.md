# 0012 鉢を LINE の家族のグループと結べるようにする

- 日付：2026-11-08

## 背景

鉢が話しかける相手は、`devices.line_user_id` の1人だけだった。11/8
のすり合わせで、発表では「初心者が家族と一緒に育てる」場面として、家族の LINE
グループに植物が話しかけるところを見せると決めた。機能凍結（11/10）まで2日しかない。

## 決定

- `line_user_id` に、ユーザー ID のかわりに LINE
  グループ（`C`）や複数人トーク（`R`）の ID
  も入れてよい。プッシュの送り先はどちらも同じ `to`
  で受け付けられるので、通知と週の日記はそのままグループに届く
- `line-webhook` は、グループからのメッセージをグループの ID
  で鉢と照らし合わせる
- グループでは、植物の名前を呼ばれたときか、公式アカウントにメンションされたとき（`mention.mentionees`
  の
  `isSelf`）だけ返事をする。毎回名前を打たなくてよいように、メンションでも答える。1つのトークに複数の鉢があれば名前を呼ばれた鉢が、名前がなければ最初に登録した鉢が答える。1対1では、名前がなくても最初に登録した鉢が答える
- グループと鉢を結ぶのは、今は SQL で行う。招待されたとき（`join`）にグループの
  ID をログに出す

## 理由

- マイグレーションも、送る側（`ingest-sensor`・`daily-diary`・15時の日照）の変更も要らず、2日で確かめられる
- 名前かメンションのときだけにすると、家族どうしの会話に毎回 Gemini
  の返事が割り込まない
- グループの中で鉢を結べる言葉（合言葉など）を作ると、知らないグループから他人の鉢を結ばれないための確認が要る。展示の鉢は自分たちで結ぶので、SQL
  で足りる

## 代替案

- 1つの鉢を、1対1とグループの両方に送る：送り先の表を新しく作り、送る側を全部直すことになる。凍結のあとに
  #34 で考える
- 送り主の名前とアイコンを鉢ごとに変える（`sender`）：1つのトークに複数の鉢を結んだときに分かりやすいが、発表には要らない。#34
  に残す
- グループの中の言葉で鉢を結ぶ：上の理由で、ログインを作るとき（#76）に合わせて考える
