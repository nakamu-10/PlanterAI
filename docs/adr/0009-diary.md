# 0009 カラ美の日記は、絵をルールで選び、文だけを Gemini に書かせる

- 日付：2026-11-06

## 背景

アプリの「記録」のページ（#36）に、毎日の記録を絵日記にして見せる（#36
で中村と決めた）。発表と見学会の見せ場にしたい。

- 絵は手描きの10枚（ひなたぼっこ、水をもらった、おしゃべり、記念日、くもり、のどがからから、おなかいっぱい、あつい、さむい、くらい）
- 見学会では鍵なしの画面（`app-public`、ADR 0006）で見せる
- 鉢が3つに増えても、そのまま動いてほしい（#10）

## 決定

- 表 `diary_entries` に、鉢ごとに1日1行入れる。バッチ `daily-diary` を pg_cron
  で毎晩21時に動かす
- 絵は、その日の記録からルールで選ぶ（`_shared/diary.ts` の
  `choosePicture`）。順番は、記念日 → 水やり → 長く続いた不調（1日の25%以上）→
  おしゃべり（3回以上）→ 日当たり → おだやかな日
- 文だけを Gemini
  に書かせる。材料は植物の種類・気分の割合・不調・水やりの回数・日当たり・話しかけられた回数で、会話の中身と関係のまとめ（`relationship_summaries`）は渡さない。失敗したら絵ごとの定型文にする
- 絵は全部の鉢で同じ10枚を使う。カラ美の絵なので、サボテンの鉢にもカラ美が出る。どの鉢でもカラ美の
  3D アバターが出るのと同じで、植物ごとの絵は凍結のあとに考える
- 気分の割合は、行の数ではなく時間で測る。日照の日次判定の行は入れない
- `{"backfill_days": 7}` で過去の分をさかのぼって作れる。今日は入れない
- 日曜は、その週の日記ができたことを LINE に定型文で送る（鉢に LINE
  が結ばれているときだけ）。ADR 0010 で、絵と文を並べる形に変えた
- 記録のページのデータは、`app-data` の `records` と `app-public` の
  `?view=records`
  が返す（`_shared/records.ts`）。鍵なしでは、会話は植物が自分から送ったセリフだけにする

## 理由

- 絵を LLM
  に選ばせないのは、状態判定をルールで行う方針（ハルシネーション対策）と同じ理由。テストもできる
- 会話の中身を渡さなければ、人が書いた文が日記に混ざらないので、日記はそのまま鍵なしで返せる。話しかけられた回数は数字なので返してよい
- 行の数で割ると、`DEMO_MODE`（5秒おき）の時間だけで割合が決まってしまう
- 水やりがあった日は、困っていた日でも水の絵にする。その日に一番残るのは「水をもらえた」ことで、文の材料には不調も入る
- 21時にするのは、日照の最終判定（20時）のあとで、日曜の LINE
  が寝る時間に届かないようにするため。21時より後の水やりはその日の日記に入らないが、絵日記としては困らない
- 週の LINE を会話の履歴に入れないのは、URL
  入りの定型文が吹き出しに出て、次のセリフの言い回しの参考にもされてしまうため
- 昼にさかのぼったときに今日まで書くと、途中までの記録で日記ができ、夜の分が飛ばされる

## 代替案

- 絵も Gemini
  に選ばせる：同じ記録で絵が変わり、確かめられない。「水分不足なのにひなたぼっこ」もありうる
- 会話の中身も材料にする：日記は面白くなるが、人が書いた文が混ざるので鍵なしで見せられない
- 絵を Gemini
  で生成する：1日ごとに費用がかかり、絵の出来を確かめられない。手描きの絵の良さもなくなる
- 開いたときにその場で作る：開かない日の日記ができず、来場者が開くたびに Gemini
  を呼ぶことになる
- 日記を `relationship_summaries`
  に入れる：人の会話から作る表なので、鍵なしで返す日記と混ぜたくない
