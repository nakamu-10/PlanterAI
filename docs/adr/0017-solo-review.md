# 0017 ひとりで開発するあいだは、AI のレビューと自分の読み直しでマージする

- 日付：2026-11-24

## 背景

- 成果発表会が終わり、地引さんがチームから抜ける。PR を見てくれる人がいなくなる
- CLAUDE.md は「PR は相手にレビューを頼む」としていた。この決まりのままでは、PR
  がマージできずに溜まる（#128〜#131 は地引さんへのレビュー依頼のまま）
- main のブランチ保護が求める承認は 0 件で、CI
  の4つ（static・test・build・secrets）だけが必須。設定の上では、今もひとりでマージできる
- 本番には、デバイスの鍵と会話の記録がある。確かめずに入れてよい規模ではない

## 決定

人のレビューの代わりに、次の4つで確かめてからマージする。手順の細かい所は
CLAUDE.md の「レビュー」にだけ書き、ここには写さない（写すと食い違うため）。

- CI が全部通る
- PR を作ったのとは別の Claude Code のセッションで `/code-review` を回し、PR
  にコメントさせる
- 中村が差分全体を、他人が書いたつもりで読む
- 本番のデータ・鍵・認証・マイグレーションに関わる PR は、一晩おいて読み直す

ほかに、次も決める。

- ひとりでもブランチと PR は続ける。PR は差分 150 行までを目安に小さくする
- Claude は、中村がその PR を「マージしてよい」と言ったときだけマージする
- 急ぎで手順を省くときは、省いた手順と理由を PR にコメントする
- 本番デプロイの `production` の承認は、今までどおり人が Summary
  を読んで押す（ADR 0011）

## 理由

ひとりで開発している人たちの実践を調べると、人のレビューの代わりに、自動の確認と、自分で読み直す手順で品質を守っていた。

- テストと CI を毎回そろえ、未完成のものは main に入れない。ほぼひとりで
  Datasette を作る Simon Willison
  は、機能に必ずテストを付け、大きな機能はブランチで作っている
  （[How I build a feature](https://simonwillison.net/2022/Jan/12/how-i-build-a-feature)）
- ひとりでも PR を開き、差分全体を他人のつもりで読むと、消し忘れなどが見つかる
  （[Using PRs more](https://lossless-group.github.io/context-vigilance-kit/corpus/lossless-monorepo/explorations/using-prs-more/)、[Alejandra Gonzalez](https://opensource.org/maintainers/blyxyas)）。小さい
  PR ほど読みやすい
- 機械的なレビューは AI
  に任せ、人の注意は判断が要る所に使う。人がコードを理解している必要がある限り、人のレビューは欠かせない
  （[ezyang, 2026](https://blog.ezyang.com/2026/04/oss-code-review-in-the-era-of-llms/)）
- 作ったセッションの Claude
  は経緯を知っていて、同じ思い込みを持つ。別のセッションなら差分だけを読む
- 差分を読んだか、一晩おいたかは、中村にしか分からない。Claude
  がマージするのを中村の一言の後に限れば、読む手順を飛ばしたマージが起きない。マージのボタンを押す手間は
  Claude に任せられる
- 自分のレビューは、人のレビューの完全な代わりにはならない。間を空けて読み直すと、書いたときの思い込みから離れられる。本番に関わる変更は戻しにくいので、そこだけ時間をかける

## 代替案

- 人のレビューを待つ：頼める人がいない。PR が溜まり、開発が止まる
- PR をやめて main に直接入れる：CI を通らないコードが main
  に入る。差分をまとめて読む機会もなくなる
- 確認用の環境を持たずに本番へ直接出す（Pieter Levels
  のやり方）：すぐ直せて、失敗しても致命的にならない規模だから成り立つ。鍵と会話の記録を持つ
  PlanterAI には合わない
- Claude
  にはマージさせない：中村が読み終えたあとのボタン押しまで中村に残り、出先ではマージできない。読む手順は一言の条件で守れる
- PR のたびに GitHub Actions で Claude に自動でレビューさせる：API の鍵を
  Secrets に入れる必要があり、使った分だけ料金がかかる。手で `/code-review`
  を回してみて、手間に感じたら考え直す

## 追記（2026-11-24）

- 出先からは新しいセッションを開けないので、レビューは、会話を引き継がない種類のサブエージェントにも頼めるようにした
- 大事なのは、PR を作った経緯を知らないことで、別のセッションかどうかではない
- 頼み方の細かい所は、CLAUDE.md の「レビュー」に書く
