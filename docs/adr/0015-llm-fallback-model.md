# 0015 Gemini が混んでいるときは、予備のモデルで作り直す

## 状況

2026-11-17 から、セリフの生成がほとんど定型文になった。`conversation_logs`
の失敗の理由は、HTTP 503 と時間切れだった。

| 日    | Gemini のセリフ | 定型文 |
| ----- | --------------- | ------ |
| 11/16 | 7               | 2      |
| 11/17 | 1               | 4      |
| 11/18 | 2               | 5      |

503 は Google 側の混雑で、こちらの設定の問題ではない。Google
のフォーラムでも、Flash 系のモデルで 503 が続く報告が今年何度も出ている。

これまでは 503 と 429 のとき、0.5
秒おいて同じモデルに投げ直していた。混んでいるモデルに投げ直しても、同じ結果になりやすい。

## 決定

- 503 と 429（`LlmHttpError` の `retryable`）のときは、予備のモデル
  `gemini-3.5-flash-lite` で作り直す。0.5 秒は待たない
- 予備も失敗したら、今と同じく定型文に回す
- 打ち切りと空の応答は、今と同じく、同じモデルで条件を変えて作り直す
- 時間切れは、今と同じく作り直さない。今のモデルを待つ時間（通知 12 秒、返事 20
  秒）も変えない
- 今のモデル `gemini-3.6-flash` は変えない

## 理由

- 503 は 4〜5 秒で返ってくることが多く、残りの時間で予備のモデルを試せる
- `gemini-3.5-flash-lite` は Stable で、思考の設定 `minimal`
  を受け付ける（Google AI Studio のドキュメントで確認）。軽いので速い

## 代替案

- 時間切れのときも予備のモデルで作り直す：ESP32 は最大 20
  秒しか待たないので、今のモデルを待つ時間を 8 秒ほどに縮めることになる。10〜15
  秒かかって作れていたセリフまで、予備のモデルに回ってしまう
- 今のモデルを新しい `gemini-3.8-flash` に替える：11 月上旬の 503
  の報告はこちらに多い。口調や長さは今のモデルに合わせて調整してあり、発表会（11/20）の前日に替えるのは危ない。発表会のあとに試す
