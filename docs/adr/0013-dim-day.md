# 0013 曇りや雨の日は、日照不足で置き場所を責めない

- 日付：2026-11-10

## 背景

カラテアの1日の目標（`lightDaily.comfortLow`）は、8月の実測から 10,000 lx·h
にしていた。10/1〜11/9
の40日では、目標に届いた日が4日に1日しかなく、15時と20時の「日照不足」がほぼ毎日届いていた。

同じ40日を Open-Meteo
の過去の天気（調布）と照らし合わせると、晴れていても暗かった日（10/9〜10/12
など）と、雨で暗かった日（10/24・10/26・11/4・11/9
など）があった。前者は置き場所を変えれば光が増えるが、後者は変えてもあまり増えない。それでも同じように「明るいところに置いて」とお願いしていた（#88）。

## 決定

- カラテアの目標を 8,000 lx·h にする。40日で足りていた日は、昼の明るさが
  1,000〜2,000 lux だった。カラテアに合う明るい日陰（約 1,000
  lux）が8時間続く量にあたる
- 15時・20時の判定で、Open-Meteo
  の今日の予報を見る。日が差した時間（`sunshine_duration`）が日の長さ（`daylight_duration`）の半分に届かない日を「曇りや雨の日」とする
- 曇りや雨の日は、15時の予告を出さない。20時は不足を伝えるが、置き場所を変えてとは頼まず、「明日は晴れるといいね」と軽く言う。不足が続いた日数にも数えない（`daily_light.kind`
  を `dim_day` で残す）
- 場所は `WEATHER_LATITUDE`・`WEATHER_LONGITUDE`
  で渡す。入れていなければ、取れなければ、これまでどおり判定する

## 理由

- Open-Meteo は鍵も登録も要らず、`fetch` だけで使える。依存を足さない
- 「半分」は、晴れの日の比が 0.9 以上、雨の日が 0〜0.4
  くらいだったので、その間に置いた
- 予報は市くらいの細かさなので、リポジトリには家の場所を書かず、関数の環境変数にする
- 20時まで黙ると、天気のせいの日にも何も届かず、アプリの吹き出しも変わらない。責めない形で1回だけ話す

## 気をつけること

- 照らし合わせた天気は調布のもの。鉢が別の場所にあれば、その場所で確かめ直す
- 晴れていても暗かった日は、これまでどおり「明るいところに置いて」と言う。これは置き場所のせいなので、言うのが正しい
- 天気を取れない時間が5秒あると、その回の `ingest-sensor` がそのぶん遅れる

## 代替案

- 目標を季節で変える：天気と季節の両方を数字で決める根拠がまだない
- 雨の日は何も言わない：LINE
  の通数は減るが、天気の日に植物が黙っていることになる
- 朝に天気をひとこと言う（#88 のコメント）：アプリの吹き出しで、発表のあとに作る
