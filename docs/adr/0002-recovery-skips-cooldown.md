# 0002 満足に戻った通知は、クールダウンを待たずに送る

- 日付：2026-11-04

## 背景

LINE
の通知には60分のクールダウンがあり、状態が境界で往復しても乱発しないようにしている。
ただ、乾いたことを通知した直後に水をやると、「満足に戻った」通知もクールダウンで止まっていた。
水やりのお礼が来ないので、育てる人には反応がないように見える。デモでも、水やりからお礼までを続けて撮れない。

## 決定

満足に戻ったときは、クールダウンを待たずに通知する。
悪化の通知は、これまでどおりクールダウンで止める。 判定は `emotionEngine.ts` の
`cooldownFor` にまとめ、`shouldNotify` と DB の `claim_state_notification`
の両方に同じ値を渡す。

## 理由

- 水やりへのお礼は、すぐに返ってくることに意味がある。後から届いても、何へのお礼か分からない
- 回復を伝えた後の悪化はクールダウンで止まるので、往復しても通知はクールダウン1回あたり2通（悪化と回復）までに収まる
- 温度や日当たりの回復も同じ扱いになり、水やりだけの特別な処理がいらない

## 代替案

- 水やりを検出したときだけ、お礼を別に送る：処理が2つになり、直後の「満足に戻った」通知と二重になりやすい
- クールダウンを短くする：悪化の通知まで増え、乱発を防ぐ目的に反する

## 追記（2026-11-04）：不調が続くときと、日照の日次判定

LINE の履歴を見直して、次の2つも直した。

- 不調を伝えたあと、満足に戻らないまま別の不調（乾燥 →
  水分不足など）になると、60分ごとにお願いが届いていた（10/31
  は6時間で4通）。不調の次の別の不調は、クールダウンを3倍（180分）あける。同じ不調の悪化や、前より強い感情の不調は60分のまま。危険域はこれまでどおり待たない
- 日照の日次判定（15時の予報、夜の結果）の通知を、センサーの判定が「最後に伝えた状態」として読んでいた。そのため今が明るいだけで「日照不足から満足に戻った」とみなし、「明るい場所に移してくれてありがとう」と送っていた。日次判定の通知は、比べる状態からは外す。ただしクールダウンには数え、日照の通知の数分後にセンサーの通知がもう1通届かないようにする
