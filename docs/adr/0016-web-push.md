# 0016 公開している鉢の通知を、ログインなしの Web Push でも送る

- 日付：2026-11-22（11/24 にレビューの指摘を入れた）

## 背景

植物の異変を知らせる道は、LINE だけになっている（#111）。

- LINE を使っていない人は、アプリを開かないと異変に気づけない
- LINE の無料プランは月200通で、家族のグループでは人数分を使う（ADR 0012）
- 世話がうまくいくほど通知が減り、アプリを開く理由もなくなる（#112）。元気が
  ないときだけでも、確実にアプリまで来てもらう道がほしい

#111 では、誰に送るかを決めるためにログイン（#76）が先に要るとしていた。
ログインは 11/22 に保留にした。

## 決定

- `public_slug` のある鉢（公開している鉢）だけ、ログインなしで通知を購読できる
  ようにする
- 送るのは、`ingest-sensor` が LINE
  に送る状態の変化のセリフと同じものだけにする。
  タイトルは「サボ太郎から」のように植物の名前、本文はセリフ、押すとその鉢の
  /app/ を開く
- 購読は新しい表 `push_subscriptions` に、鉢と結んで入れる。列は `device_id`、
  `endpoint`、`p256dh`、`auth`、`created_at`。一意にするのは （`device_id`,
  `endpoint`）の組にし、1つのブラウザで複数の鉢を購読できるようにする
- 送る直前に、鉢がまだ `public_slug`
  を持っているかを確かめる。公開をやめた鉢には送らず、 その鉢の購読を消す
- 購読と解除は、新しい関数 `app-push` が受ける。鍵は要らず、`pot`
  （`public_slug`）と購読の情報を受け取る
- `app-push` は、購読の `endpoint` が既知のプッシュサービスの https の URL
  のときだけ受け付ける。ホスト名で決める（作るときに、各ブラウザのドキュメントで今のホストを確かめる）
  - Chrome・Android：`fcm.googleapis.com`
  - Firefox：`updates.push.services.mozilla.com`
  - Safari・iPhone：`web.push.apple.com`
  - Edge：`*.notify.windows.com`
- 1つの鉢の購読の数に上限を設ける。上限に達したら、その鉢の古い購読から消して入れる
- 送ったときに 404・410 が返った購読は、表から消す。403
  が返った購読も消す（VAPID の鍵を替えると、古い購読はずっと 403 を返す）
- LINE に送るかどうかにかかわらず、セリフを `conversation_logs`
  に残したあとに送る。LINE と結んでいない鉢（ADR 0008）にも届く
- ESP32 への応答は待たせない。Web Push
  は応答のあとに送る（`EdgeRuntime.waitUntil`）
- 送るときの `TTL`
  は数時間にする。オフラインのあいだに溜まった「お水がほしい」が、水をやったあとに届かないようにする
- 通知センターには、鉢ごとに最新の1つだけを残す。Service Worker の
  `showNotification` で `tag` を鉢ごとにし、対応しているサービスには `Topic`
  ヘッダーも鉢ごとに付ける
- VAPID の鍵は、公開鍵を Vercel の `VITE_VAPID_PUBLIC_KEY`、秘密鍵を関数の環境
  変数 `VAPID_PRIVATE_KEY` に入れる。秘密鍵は `VITE_` に入れない。JWT の `sub`
  に入れる連絡先（`mailto:` か https の URL）も、環境変数 `VAPID_SUBJECT`
  に入れる（無いと Apple のサービスが 403 を返す）。足した環境変数は
  `.env.example` にも書く
- アプリは /app/ に Service Worker を置く。「通知を受け取る」ボタンを押したとき
  だけ、通知の許可を聞く
- iPhone は、ホーム画面に追加して独立した画面で開いたアプリでしか Web Push
  を受けられない。 /app/ 用の
  manifest（`display: standalone`）を作ってから、ホーム画面に追加して押すよう案内する

## 理由

- 送るセリフは、植物が自分から話したものだけで、`app-public` の
  `last_plant_message` で誰でも見られる。人が書いた文と人への返事は送らない（ADR
  0006 と同じ線引き）
- ただし `app-public` は最新の1つしか見せないが、Web Push
  は届いた分が通知センターに溜まる。`tag`
  を鉢ごとにして最新の1つだけを残し、過去のセリフが並ばないようにする
- `app-public` は読み取りだけの関数にしてある（ADR
  0006）。購読は書き込みなので、関数を分ける
- `endpoint` を確かめないと、関数に任意の URL へ POST させる道（SSRF）になる。
  上限が無いと、鍵なしの書き込みで表を埋められる
- 上限に達したときに新しい購読を断ると、偽の購読で埋められたあとは、本物の人がずっと購読できなくなる。古い購読から消せば、埋められても新しく購読した人には届く
- 公開をやめた鉢に送り続けると、見せないと決めたセリフが購読した人に届き続ける
- 送る相手が多いと、ESP32 の待ち時間（最大20秒）に響く。セリフの生成で 10 秒
  以上かかることがあるので、そのあとに待つ処理を足さない
- 通知を状態の変化だけにするのは、上限が無い分うるさくなりやすいため。良い知らせ
  は、通知ではなくアプリの中で伝える（#112）

## 代替案

- ログイン（#76）を先に作る：持ち主だけに送れるが、2〜3日かかり、11/22
  に保留にした。公開している鉢は、ログインが無くても送ってよい中身しか送らない
- LINE を使い続ける：LINE を使っていない人に届かず、通数の上限もある
- 購読を `app-public` に足す：読み取りだけの関数に、鍵なしの書き込みが入る
- 日照の予告・日記・週のまとめも Web Push で送る：まず状態の変化だけで、
  うるさくないかを見る

## 決めていないこと

- 送るライブラリ：Deno と Web Crypto で動く `jsr:@negrel/webpush` か
  `@pushforge/builder` を、作るときに今の版とドキュメントを確かめて選ぶ。
  依存を足す前に確認を取る
- iPhone でホーム画面から開いたときの鉢：/app/ 用の manifest の `start_url` には
  `?pot=` が付かない。最後に見た鉢を覚えて開くようにするかを、作るときに決める
- 購読の上限の数
- ログインを作ったら、持ち主の非公開の鉢にも送るか
