# 0006 展示の /app/ は、鍵なしで読める app-public で動かす

- 日付：2026-11-05

## 背景

11/20 の見学会と発表は
C（展示用に機能を絞る）にし、ログインは発表のあとに作る（#10、ADR 0003）。

- /app/ の `app-data`・`app-chat` はデバイスキーで認証している。キーを
  `VITE_DEVICE_KEY` に入れると、配る JS から誰でも読めるので、本番の /app/
  には入れていない。そのため、本番の /app/ は実データを読めない
- 来場者は QR から開くので、ログインもできない
- 鉢を3つに増やし、URL で鉢を選べるようにしたい（#10、#36）

## 決定

- 読み取りだけの Edge Function `app-public` を足す。`GET ?pot=<名前>`
  で、鍵なしで鉢の様子を返す
- 鉢は `devices.public_slug` で選ぶ。この列が入っている鉢だけが見える
- 返すもの：植物の名前・性格・登録日、センサーの `filtered` と
  `scores`、気分の記録、最後の水やり、植物が自分から送った最後のセリフ。形は
  `app-data` の `dashboard` に合わせる
- 返さないもの：`device_key`・`devices.id`・`line_user_id`、センサーの
  `raw`、人が書いた文、人への返事、関係のまとめ（`relationship_summaries`）
- 設定の変更とチャットは、今のまま鍵の要る `app-data`・`app-chat`
  だけが受ける。/app/ は鍵が無いと `app-public` を使い、設定とチャットを出さない
- 来場者にチャットさせるかは #10 で決める

## 理由

- `app-data`
  に鍵なしの道を足すより、関数を分けた方が、鍵なしで届くのは読み取りだけだとコードで分かる。`app-data`
  の書き込みに鍵なしで届く道を、うっかり作らずに済む
- 名前を入れた鉢だけを見せるので、鉢を足しても勝手には公開されない。URL に
  `devices.id` を出さずに済む
- 人への返事は、その人が書いた内容に触れていることがある（「けんかしちゃったの？」など）。`line-webhook`・`app-chat`
  は人の行の 1ms
  あとに返事を書くので、直前が1分以内の人の行なら返事とみなして飛ばす。直前の行が取ってきた範囲の外にあって分からないときも、出さない
- 関係のまとめは、人が書いた会話から作るので返さない
- 植物が自分から送るセリフにも、会話の流れで人の話が混ざることはある。展示の鉢の
  LINE には、来場者に見られて困ることを書かないことで補う

## 代替案

- `app-data` に `pot`
  を足し、鍵が無ければ読み取りだけにする：1つの関数の中で、鍵の有無で道が分かれる。書き込みの道に鍵なしで届かないことを、毎回レビューで確かめることになる
- アプリ用に別のキーを配る（ADR 0003 の
  B）：キーをブラウザに置くので、読めた人はそのキーでできることを全部できる
- 会話を返さない：水やりのあとの「満足に戻った」通知が、開いているアプリに出なくなる。デモの見せ場が減る
- `conversation_logs` に、返事か通知かの列を足す：書く所が4つあり、`_shared/`
  を変えると関数を全部デプロイし直すことになる。機能凍結（11/10）の前には避ける
